# Bilibili 竖屏优化

在 Bilibili 原生竖屏 Story 视频流中提供以下功能：

- 移除「上滑观看」提示。
- 关闭直播预览倒计时自动进入直播间，保留直播预览及手动进入。
- 清理左下角下载卡片、游戏推广大卡片、粉色推广按钮，以及带蓝色跳转链接的推广评论卡片。此项为新增功能，已通过离线抓包回放，仍待手机实测。

首页视频入口和横竖屏切换沿用 App 原生逻辑；保留视频条目和播放参数。视频画面里自带的广告内容仍会播放。

## 安装与更新

适用于 Loon 3.5.1（983）及以上版本。在 Loon 插件页面添加远程订阅：

```text
https://raw.githubusercontent.com/LuxJon/Loon-Rules/main/Plugins/Bilibili/Bilibili.lpx
```

已经订阅此地址的用户，更新原插件即可，无需更换地址或额外添加插件。

开启复写及 MitM，安装并信任 Loon 证书；插件解密域名为 `app.bilibili.com`。所有功能直接通过内置 JSON/JQ 复写实现，无需下载或添加 JS，也无需开启脚本开关。

更新后，停用旧版三合一插件、空间直达试验版、单独的竖屏广告清理测试插件及同功能重复配置。彻底退出 Bilibili 并重新打开，刷新原生竖屏视频流后测试，避免旧页面缓存影响观察。

## 处理范围与兼容性

仅匹配下列两个接口（含查询参数），只处理 HTTP 200、`code=0` 的 JSON 响应。

### 竖屏 Story 视频流

`https://app.bilibili.com/x/v2/feed/index/story`

同一条规则先执行旧版已有的两项处理，原有 JQ 逻辑及 URL 匹配范围保持不变：

- 删除对象类型视频项中的 `data.items[*].scroll_guide`。
- 将已有的 `data.config.live_auto_enter.enable` 设为 `false`，保留其他直播配置；不补写缺失的开关。

随后仅对 `ad_info` 为对象的视频项清理：

- `story_cart_icon`：推广购物入口。
- `ad_info.extra.card.button`：推广按钮。
- `ad_info.extra.card.forward_reply`：左下推广评论卡片，不是评论区内的全部评论。
- `ad_info.extra.card.story_style_selection_module`：含 `basic_card`、`reinforced_card` 的推广样式模块。

不删除视频项，不改写视频地址、播放参数、UP 信息、互动统计或广告标识。缺失字段和不符合结构的字段保持原样。

### 动态推广卡片

`https://app.bilibili.com/x/v2/feed/index/story/cart`

移除 `data.anchor`；若 `data.ads` 为数组则清空。保留响应状态、业务码和其他字段。这两种广告返回结构均在本次抓包中出现。

## 验证情况与限制

2026-10-19 合并版本完成以下离线检查：

- 旧版完整 JQ 作为合并规则的第一段保留；URL、最低 Loon 版本、图标及 MitM 域名沿用原配置。
- 对 63 组无新增广告组件的构造响应，与旧版逐字段比较，输出完全一致；覆盖字段缺失、异常结构以及直播开关的不同状态。
- 回放用户提供的 13 条相关请求：8 条 Story、5 条卡片请求，各有原始与已有改写后两份响应，共 26 份响应快照。
- 对照旧版输出核查全部 82 个视频条目快照：58 个普通视频项与旧版一致；24 个广告视频项仅额外删除上述推广组件。保留视频条目数量、顺序、视频参数及其他字段。
- 在抓包中确认旧功能仍移除上滑提示字段，并关闭 8 个原始响应中的直播自动进入开关；另检查了保留倒计时、预览和手动入口等配置的构造场景。
- 检查重复执行、URL 边界、业务错误响应和大整数 ID。测试基于官方 jq 1.8.2，原始抓包未上传到本仓库。

以上验证的是响应数据处理，尚未确认 Loon 内置 JQ 的运行结果和手机端控件渲染。新增推广清理是否完全隐藏、是否留下空白或回退成其他样式，仍需 iPhone 实测。原有功能也不应将离线检查视为对所有 App 版本的兼容承诺。

当前版本不包含 UP 空间直达及相关 JS、诊断或试验功能。若其他插件也改写上述接口，可能发生执行顺序或响应脚本冲突，建议先单独启用本插件测试。

如果更新后仍有广告，请提供对应页面截图，以及相关接口的新原始响应和改写后响应，以区分规则未命中与字段变化。如果发生播放异常，先停用本插件回退，再保留出问题的响应供定位。
